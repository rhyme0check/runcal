# RunCal 일정 관리

RunCal은 폰 앱이다. PC에서는 앱에 직접 접근할 수 없으므로 앱이 읽는 원본(Notion·구글 캘린더)을 고친다.
폰의 RunCal은 앱을 열 때, 1시간마다, 위젯의 ↻ 버튼으로 변경 내용을 받아온다.

## 어디에 있는 일정인가

| 일정 | 저장 위치 | PC에서 |
|---|---|---|
| 러닝·훈련(세션) | Notion **훈련일지** DB | Notion 연동으로 조회·수정 |
| 일반 일정(회의·약속 등) | 구글 계정의 **기본(primary) 캘린더** | 구글 캘린더 연동으로 조회·수정 |
| 공휴일 | 구글 공휴일 캘린더 | 조회만 |
| RunCal 로컬 캘린더 | 폰 안에만 있음 | 접근 불가 → .ics 파일로 전달(아래) |

어느 쪽인지 애매하면 러닝·훈련은 Notion, 그 밖은 구글 캘린더로 본다. 그래도 애매하면 묻는다.

## Notion 훈련일지 DB

| 속성 | 타입 | 용도 |
|---|---|---|
| 세션 | 제목 | 훈련 이름(형식은 아래) |
| 날짜 | 날짜 | 훈련일. 대부분 날짜만(종일) |
| 상태 | 선택 | `Planned` · `Done` · `Incomplete` · `Failed` 중 하나 |
| 일지 | 텍스트 | 실행 기록·메모. 사용자가 요청할 때만 읽거나 고친다 |

상태 의미: `Planned` 예정, `Done` 계획대로 완료, `Incomplete` 하긴 했지만 일부만, `Failed` 못 함.

세션 제목 형식(기존 항목과 같은 형식으로 쓴다):

- `REST` 휴식
- `EASY 8km(cap145)` 이지런, 괄호는 심박 상한
- `RP 4km*2(422)+2min+2+2` 레이스 페이스: 거리×반복(페이스 4'22")+휴식+워밍업·쿨다운
- `LSD …`, `REC …`(회복주), `RACE …`
- `STR-A 20min`, `COR-C 20min`, `PLY-B 20min` 근력·코어·플라이오(문자는 루틴 종류)
- 여러 개는 ` + `로 잇는다: `EASY 8km(cap145) + 힐스트라이드 10s*6`

## 변경 규칙 (반드시 지킬 것)

1. **먼저 조회하고 보여준다.** 바꿀 항목을 날짜·세션·상태로 표로 보여주고, 바꾸면 어떻게 되는지(전 → 후)를 함께 쓴다. 사용자가 확인하기 전에는 쓰지 않는다.
2. **Notion은 날짜와 상태만** 바꾸는 것이 기본이다. 세션 이름·일지는 사용자가 분명히 요청했을 때만 고친다.
3. **삭제(보관)하지 않는다.** 사용자가 "삭제"를 명시하면 대신 상태를 `Failed`로 바꿀지 먼저 묻는다.
4. **새 Notion 페이지는 사용자가 명시적으로 "추가"를 요청했을 때만** 만들고, 위 제목 형식과 `상태 = Planned`로 만든다.
5. **한 번에 20건까지.** 10건이 넘으면 목록을 꼭 다시 확인받는다.
6. **쓰기 직전에 다시 읽는다.** 목록을 보여준 뒤 그 항목이 Notion에서 바뀌었으면(날짜·상태·최종 수정 시각이 다르면) 그 항목은 쓰지 않고 알린다.
7. 날짜만 옮길 때 기존 시각·기간은 유지한다. 종일 항목은 날짜만(`YYYY-MM-DD`) 쓴다.
8. 실행 후 바뀐 내역(전 → 후)을 표로 남겨, 사용자가 되돌리기를 요청하면 그 표대로 원래 값을 다시 쓴다.

## 날짜 해석

- 시간대는 **Asia/Seoul**. 한 주는 **월요일**에 시작한다.
- "다음 주 화요일"은 다음 주 월~일 범위 안의 화요일이다.
- 연도 없는 날짜는 오늘에 가장 가까운 해로 본다.
- "하루씩 밀어줘"처럼 여러 건을 옮기면 겹치는 날이 생기는지 확인해 표에 표시한다(예: 두 세션이 같은 날이 됨).

## 구글 캘린더 일정

- 새 일정은 구글 계정의 기본(primary) 캘린더에 넣는다.
- 일정 유형별 색(구글 색 이름). 사용자가 앱에서 정한 유형과 다르면 사용자의 말을 따른다.

  | 유형 | 색 |
  |---|---|
  | 업무 | Basil(초록) |
  | 미팅 | Banana(노랑) |
  | 휴가 | Tomato(빨강) |
  | 러닝 | Tangerine(주황) |

- 구글 캘린더도 위 변경 규칙 1, 5, 6, 8을 똑같이 따른다. 삭제는 사용자가 명시했을 때만 한다.

## 폰에만 둘 일정 (.ics)

PC에서는 RunCal 로컬 캘린더에 쓸 수 없다. 사용자가 "폰에만", "RunCal 캘린더에" 같은 요청을 하면 `.ics` 파일을 만들어 준다.
폰에서 그 파일을 RunCal로 공유하면 확인 화면에서 골라 추가할 수 있다.

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//RunCal skill//KO
BEGIN:VEVENT
UID:<임의의 고유값>@runcal
SUMMARY:<제목>
DTSTART;TZID=Asia/Seoul:20261007T070000
DTEND;TZID=Asia/Seoul:20261007T080000
LOCATION:<장소, 없으면 줄 생략>
END:VEVENT
END:VCALENDAR
```

종일 일정은 `DTSTART;VALUE=DATE:20261018` / `DTEND;VALUE=DATE:20261019`(끝 날짜 다음 날)로 쓴다. 한 파일에 여러 VEVENT를 넣어도 된다.

## 답변 형식

- 한국어로 짧게. 일정 목록은 `날짜(요일) · 세션/제목 · 상태` 표로.
- 쓰기 전에는 "아직 바꾸지 않았습니다"를 분명히 한다.
- 실행 후에는 "폰 RunCal은 앱을 열거나 위젯 ↻를 누르면 반영됩니다"를 한 줄 덧붙인다.
